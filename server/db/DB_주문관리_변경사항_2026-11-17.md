## 2. 테이블과 칸 이름 대응

제안서와 달라진 이름만 적었습니다. 나머지는 제안서와 같습니다.

| 테이블 | 제안서 | 확정 | 이유 |
|---|---|---|---|
| `orders` | `phone` | `customer_phone` | 무엇의 연락처인지 드러나게 |
| | `address` | `shipping_address` | |
| | `total` | `total_amount` (int unsigned, 원) | |
| | `status` | `order_status` | 라인 테이블의 `processing_status`, `electrical_status`와 같은 규칙 |
| | (없음) | `accepted_at` | 주문 관리 프로그램이 검사를 통과시킨 시각 (`order/accepted`의 `accepted_at`) |
| `order_items` | `id` | `order_item_id` (bigint unsigned) | 라인 테이블 키 규칙 (`cycle_id`, `defect_id` …) |
| | `name` / `qty` / `price` | `product_name` / `quantity` / `unit_price` | |
| `order_status_log` | `id` | `status_log_id` | |
| | `from_status`, `to_status` | 상태 enum 5종 | 잘못된 상태가 들어가지 않게 |
| `stock` | `packs` | `stock_packs` | |
| `stock_log` | `id`, `delta`, `reason` | `stock_log_id`, `delta_packs`, `reason` enum(`restock`,`delivered`,`adjust`) | |
| | (없음) | `packs_after`, `changed_by`, `source_event_id` | 변경 뒤 팩 수, 바꾼 사람, 중복 방지 키 |
| `order_runs` | `source_run_id` varchar(20) | char(20) ascii_bin | `runs.source_run_id`와 같은 형식이어야 조인할 때 인덱스를 씀 |
| | (없음) | `linked_at` | 연결한 시각 |
| `inquiries` | `inquiry_id` varchar(32) | `inquiry_id` varchar(20) | 문의번호 `Q-YYYYMMDD-XXXX` (메시지의 `no`) |
| | `name`, `phone` | `customer_name`, `customer_phone` | `orders`와 같게 |
| | (없음) | `inquiry_type` enum(`delivery`,`cancel`,`product`,`bulk`,`etc`) | 문의 유형 (메시지의 `type`). 칸 이름에 테이블 이름을 붙이는 규칙 (`order_status`와 같음) |
| | (없음) | `answered_by` | 답변한 사람 |

- 시각은 모두 `datetime(3)`, 한국 시간입니다 (라인 테이블과 같음).
- `order_items`, `order_status_log`, `order_runs`, `stock_log`의 `order_no`는 `orders`에 외래 키로 연결했습니다.
- `inquiries.order_no`는 고객이 직접 적는 값이라 틀릴 수 있어서 외래 키를 걸지 않았습니다.
- 주문 테이블에는 연락처와 주소가 들어갑니다. 시연에는 예시 데이터만 씁니다.

## 3. 저장하는 토픽

| 토픽 | 저장 테이블 | 하는 일 |
|---|---|---|
| `order/accepted` | `orders`, `order_items`, `order_status_log` | 검사를 통과한 주문 저장, 첫 상태 기록(`NULL` → `received`, 시각 = 주문 `ts`) |
| `order/status/+` (retained) | `orders`, `order_status_log` (+ `stock`, `stock_log`) | 상태·택배사·송장 변경, 배송 완료면 재고 차감 |
| `order/stock` | `stock`, `stock_log` | 입고(`restock`), 수량 수정(`adjust`) |
| `order/run` | `order_runs` | 주문과 라인 회차 연결 |
| `inquiry/accepted` | `inquiries` | 검사를 통과한 문의 저장 |
| `inquiry/answer/+` (retained) | `inquiries` | 답변 저장 |

저장하지 않는 토픽: `order/new`, `order/ack`, `order/cancel`, `inquiry/new`, `inquiry/ack` (홈페이지 ↔ 주문 관리 사이 메시지)

## 4. 메시지 형식 (주문 통신 규약 3·4장 그대로)

```json
// order/accepted — order/new와 같은 내용 + accepted_at
{"no":"BR-20261117-7K3Q","ts":"2026-11-17 10:30:00.000","name":"홍길동","phone":"010-1234-5678",
 "addr":"서울 …","memo":"","items":[{"id":"aa12","name":"AA 알카라인 12개입","qty":2,"price":8900}],
 "total":17800,"accepted_at":"2026-11-17 10:30:00.400"}

// order/status/BR-20261117-7K3Q (retained)
{"no":"BR-20261117-7K3Q","status":"shipping","ts":"2026-11-17 15:02:11.000",
 "courier":"CJ대한통운","tracking":"612345678901","cert_no":null,"by":"관리자"}

// order/stock — restock: packs만큼 더함 / adjust: 창고 팩 수를 packs로 맞춤
{"event_id":"32자리16진수","ts":"2026-11-17 09:00:00.000","product_id":"aa4","kind":"restock","packs":10,"by":"관리자"}

// order/run
{"no":"BR-20261117-7K3Q","run_id":"20261117-101500-ab12","battery_count":8,"ts":"2026-11-17 14:00:00.000"}

// inquiry/accepted
{"no":"Q-20261117-M8TA","ts":"2026-11-17 10:40:00.000","name":"홍길동","phone":"010-1234-5678",
 "type":"cancel","order_no":"BR-20261117-7K3Q","question":"주문을 취소하고 싶어요."}

// inquiry/answer/Q-20261117-M8TA (retained)
{"no":"Q-20261117-M8TA","answer":"주문 취소 처리했습니다.","by":"관리자","ts":"2026-11-17 11:02:00.000"}
```

| 필드 | 저장 프로그램 검사 | DB 칸 |
|---|---|---|
| 주문 `no` | `BR-` + 날짜 8자리 + `-` + 영문·숫자 4자리 | `order_no` |
| 문의 `no` | `Q-` + 날짜 8자리 + `-` + 영문·숫자 4자리 | `inquiry_id` |
| `ts` | `YYYY-MM-DD HH:MM:SS.mmm` | `received_at` / `changed_at` / `asked_at` / `answered_at` |
| `accepted_at` | 같은 시각 형식. 없으면 NULL로 저장 | `orders.accepted_at` |
| `name`, `phone`, `addr` | 1~50자, 1~20자, 1~255자 (주소 필수) | `customer_name`, `customer_phone`, `shipping_address` |
| `memo` | 0~255자. `""`는 NULL로 저장 | `memo` |
| `items[]` | 1개 이상. `id` 1~10자, `name` 1~50자, `qty` 1 이상, `price` 0 이상 | `order_items` |
| `total` | 0 이상 정수 | `total_amount` |
| `status` | `received` / `inspect` / `shipping` / `delivered` / `canceled` | `order_status`, `to_status` |
| `courier`, `tracking` | 0~30자. 생략·`null`·`""`이면 저장된 값 유지 | `courier`, `tracking_no` |
| `by` | 1~50자, 생략 가능 | `changed_by` / `answered_by` |
| `type` | `delivery` / `cancel` / `product` / `bulk` / `etc` (필수) | `inquiry_type` |
| `question`, `answer` | 1~10,000자 | `question`, `answer` |

- 토픽 끝의 번호와 `no`가 다르면 형식 오류로 거부합니다 (`order/status/+`, `inquiry/answer/+`).
- 주문 관리 프로그램이 이미 검사한 메시지라서, 연락처 자리 수·`qty` 1~99·가격표 확인은 저장 프로그램에서 다시 하지 않습니다. DB 칸에 들어가지 않는 값만 막습니다.
- `cert_no`(성적서 번호)는 형식이 아직 정해지지 않아서 저장하지 않습니다 (받아도 오류 없음). 형식이 정해지면 `orders`에 칸을 추가하겠습니다.

## 5. 저장 규칙

| 상황 | 처리 |
|---|---|
| 같은 `order/accepted`가 두 번 옴 (QoS 1) | 주문번호가 이미 있으면 무시 |
| 첫 `received` 상태 메시지 (시각 = 주문 `ts`) | 주문 저장 때 남긴 첫 기록과 같아서 중복으로 처리. 기록은 한 줄 |
| 같은 상태 메시지가 다시 옴 / retained라 다시 연결할 때마다 옴 | (`order_no`, `to_status`, `changed_at`) 고유 키로 한 번만 저장. 재고도 다시 빼지 않음 |
| 처음 보는 주문번호의 상태·회차 메시지 | 거부 (로그에 `Rejected … unknown order`) |
| 이미 저장된 상태보다 오래된 상태 메시지 | 거부 (현재 상태를 되돌리지 않음) |
| `delivered`·`canceled`에서 다른 상태로 변경 | 거부. 같은 상태로 송장만 고치는 것은 허용 |
| `delivered`로 바뀜 | 그 주문의 상품별 수량만큼 `stock`에서 빼고 `stock_log`에 `delivered`로 기록 |
| 재고가 음수가 됨 | 저장은 하고 경고 로그를 남김 (입고 기록보다 많이 나간 것) |
| `stock`에 없는 상품 | 0에서 시작하는 행을 만들고 계산 |
| 같은 `event_id`의 재고 메시지 | 한 번만 반영 |
| 같은 주문·회차의 `order/run`이 다시 옴 | 건전지 수를 새 값으로 바꿈 |
| 같은 문의번호의 `inquiry/accepted`가 다시 옴 | 무시 |
| 답변을 고쳐서 다시 보냄 (`ts`가 더 늦음) | 답변을 새 값으로 바꿈 |
| retained 답변이 다시 옴 / 저장된 것보다 오래된 답변 | 무시 (같은 시각이거나 더 이름) |
| 처음 보는 문의번호의 답변 | 거부 (로그에 `Rejected … unknown inquiry`) |

- 거부된 메시지는 기존 형식 오류와 같이 **로그를 남기고 받았다고 응답**합니다. 다시 와도 똑같이 거부되기 때문입니다.
- MySQL 오류일 때는 기존처럼 응답하지 않고 다시 연결합니다. 브로커가 다시 보내 주면 그때 저장합니다.
- 시작할 때 주문 테이블이 있는지 확인합니다. 하나라도 없으면 아래 경고를 남기고 **주문 토픽을 구독하지 않습니다.** 라인 저장은 그대로 동작합니다.
  `Order tables missing (...); order and inquiry topics will not be subscribed`
- 저장 프로그램은 다시 연결해도 예전 구독이 남는 방식(CleanSession=false)이라, 첫 초안의 `order/new`, `inquiry/new`, `inquiry/answer` 구독은 접속할 때마다 해제합니다.

## 6. 적용 순서

1. **DB가 이미 있는 PC**: `DB_변경_2026-11-17_주문.sql` 실행. 이미 있는 테이블은 건너뛰므로 다시 실행해도 됩니다.
   **새로 만드는 PC**: 갱신된 `teamproject.sql`로 생성
   - 오늘 오전에 보낸 첫 버전 스크립트를 이미 실행했다면, 스크립트 아래쪽 주석 두 줄(`inquiries` 지우기, `accepted_at` 추가)을 먼저 실행한 뒤 다시 실행하세요.
2. 주문 관리 프로그램이 조회할 읽기 전용 계정에 권한 주기. 스크립트 맨 아래에 주석으로 넣어 두었습니다 (`ui_reader@localhost` 기준, 계정 이름이 다르면 바꿔서 실행)
3. `mqtt_db_writer.py`를 바꾸고 다시 실행
4. 시작 로그의 `Subscribed to …` 목록에 `order/accepted`, `inquiry/accepted`, `inquiry/answer/+`가 보이면 끝

기존 라인 테이블과 데이터는 바꾸지 않습니다.

## 7. 검증

- SQLite로 같은 테이블 구조(칸 이름·NOT NULL·고유 키·외래 키·CHECK)를 만들어 28가지 경우를 시험했고 모두 통과했습니다.
  - **주문 통신 규약 3·4장 예시 메시지 6개를 그대로 저장** (첫 `received`가 한 줄만 남는 것 포함)
  - 새 주문·중복 주문·형식 오류 6종, retained 상태 재수신
  - 상태 변경과 송장 유지, 배송 완료 재고 차감과 중복 차감 방지, 최종 상태 변경 거부, 오래된 메시지 거부, 없는 주문 거부
  - 입고·수량 수정·중복 이벤트, 회차 연결 갱신
  - 문의 저장·중복, 답변 저장·retained 재수신·고친 답변·오래된 답변·없는 문의, 문의 유형 오류
  - 라인 결과·장비 이벤트 저장이 그대로인지, 성적서 쿼리 조인 결과
  - 거부·저장·MySQL 오류 때 응답 여부, 주문 테이블이 없을 때 구독 제외, 예전 토픽 구독 해제
- **실제 MySQL 8.2와 브로커에서는 아직 실행해 보지 않았습니다.** 서버 PC에서 테스트 DB에 먼저 실행해 주세요. `INSERT … AS new ON DUPLICATE KEY UPDATE` 문법은 MySQL 8.0.19 이상이 필요합니다 (8.2는 됨).
