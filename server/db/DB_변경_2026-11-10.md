# DB · 저장 프로그램 변경 사항 (2026-11-10)

대상 파일: `server/db/teamproject.sql`, `server/db/mqtt_db_writer.py`
함께 보낼 파일: `mqtt_db_writer.md`(프로그램 전체 코드), `DB_변경_2026-11-10.sql`(이미 있는 DB용)

## 1. 한눈에

| # | 항목 | DB | 저장 프로그램 |
|---|---|---|---|
| 1 | 등급 `NG_VISUAL`, `NG_VOLTAGE` 추가 | `battery_cycles.final_grade` enum에 추가 | `grade` 허용 값에 추가 |
| 2 | 배출 위치 `NG_VISUAL_BOX`, `NG_VOLTAGE_BOX` 추가 | 변경 없음 (`varchar(64)`) | `dest` 허용 값에 추가 |
| 3 | 외관 불량 종류를 목록(`defects`)으로 저장 | `visual_defects.camera` 칸 추가 | 목록 항목마다 한 행 저장 |
| 4 | `server/events`의 `device` 20자 → 64자 | 변경 없음 (`equipment_name`은 이미 64자) | 길이 제한 변경 |
| 5 | `vision/result`, `event/mega` 원문 기록 | `communication_logs.message_kind`에 `EVENT` 추가 | 두 토픽 구독, `EVENT`로 기록 |
| 6 | MySQL 연결 재사용 | - | 연결 하나를 계속 사용 |

예전 값 `NG`, `NG_BOX`는 **이전 데이터용으로 그대로 남겨 두었습니다.** 저장 프로그램도 계속 받습니다.

## 2. 메시지 형식 (보내는 쪽 참고)

### 등급과 배출 위치

| 판정 | `grade` | `dest` |
|---|---|---|
| A | `A` | (AGV 미정) |
| B | `B` | `B_BOX` |
| 외관 불량 | `NG_VISUAL` | `NG_VISUAL_BOX` |
| 전압·내부저항 불량 | `NG_VOLTAGE` | `NG_VOLTAGE_BOX` |
| 극성 반대 등 재분류 | `RESORT` | `RESORT_BOX` |

### 외관 불량 (`server/results`의 `vision`)

```json
"vision": {"status": "ok", "result": "defect", "conf": 0.91, "polarity": "minus_up",
           "defects": [{"type": "scratch", "conf": 0.91, "cam": "front"},
                       {"type": "dent", "conf": 0.85, "cam": "back"}]}
```

| 들어온 값 | `visual_inspections.visual_result` | `visual_defects` |
|---|---|---|
| `result: "normal"` | `PASS` | 저장 안 함 |
| `result: "defect"` + `defects` 목록 | `FAIL` | 항목마다 한 행 (`type` → `defect_type`, `conf` → `confidence`, `cam` → `camera`) |
| `result: "defect"` + 빈 목록 | `FAIL` | 저장 안 함 |
| `status: "failed"` | `ERROR` | 저장 안 함 |
| 예전 형식 `result: "scratch"` (목록 없음) | `FAIL` | 한 행 (`camera`는 NULL) |
| `result: "normal"`인데 `defects`가 있음 | - | **형식 오류로 거부** |

- `defects` 항목: `type` 1~64자 (필수), `conf` 0~1 (생략 가능), `cam` 1~16자 (생략 가능)
- 불량 종류가 늘어도 형식은 그대로입니다.

### 알림 토픽 기록 (`communication_logs`)

| 토픽 | `message_kind` | `device` |
|---|---|---|
| `vision/result` | `EVENT` | `yolo` |
| `event/mega` | `EVENT` | `mega` |
| `cmd/+`, `res/+`, `ui/cmd` | 기존과 같음 | 기존과 같음 |

`event/estop`은 지금처럼 `emergency_stop_events`에 저장합니다.

## 3. 변경 없음 (확인)

- 역극성(`reversed`)일 때 `v_open`은 null로 저장 (기존 처리 그대로)
- `event/estop`, `sensor/env`는 장치 이름만 `pi` → `mega`로 바뀜. 형식이 같아서 수정 없음

## 4. 적용 순서

1. **DB가 이미 있는 PC**: `DB_변경_2026-11-10.sql` 실행 (아래와 같은 내용)
   **새로 만드는 PC**: 갱신된 `teamproject.sql`로 생성
2. `mqtt_db_writer.md`의 코드를 `mqtt_db_writer.py`로 저장하고 다시 실행
3. 시작 로그에 경고가 없으면 끝. 아래 경고가 나오면 1번이 빠진 것입니다.
   - `visual_defects.camera is missing` → 카메라 이름만 빼고 저장
   - `communication_logs.message_kind has no EVENT` → `vision/result`, `event/mega` 기록 안 함

1번을 빠뜨려도 프로그램은 멈추지 않고, 나머지는 정상으로 저장합니다.

```sql
USE `aa_battery_inspection`;

-- 등급 5종 (이미 했으면 다시 해도 같음)
ALTER TABLE `battery_cycles`
  MODIFY `final_grade` enum('A','B','NG','RESORT','NG_VISUAL','NG_VOLTAGE') DEFAULT NULL
  COMMENT 'NG는 이전 데이터용. 새 데이터는 NG_VISUAL(외관 불량) / NG_VOLTAGE(전압·내부저항 불량)',
  ALGORITHM=INSTANT;

-- 불량을 찾은 카메라 (이미 있으면 Duplicate column 오류 → 건너뜀)
ALTER TABLE `visual_defects`
  ADD COLUMN `camera` varchar(16) DEFAULT NULL COMMENT '불량을 찾은 카메라 (top / front / back)' AFTER `confidence`,
  ALGORITHM=INSTANT;

-- 알림 토픽 기록용 EVENT
ALTER TABLE `communication_logs`
  MODIFY `message_kind` enum('COMMAND','RESPONSE','OPERATOR_COMMAND','EVENT') NOT NULL,
  ALGORITHM=INSTANT;
```

모두 기존 값 뒤에 붙이거나 칸을 추가하는 변경이라 **기존 데이터는 바뀌지 않습니다.**

## 5. MySQL 연결 재사용

- 전에는 메시지마다 연결을 새로 열고 닫아서 서버 PC에 끊긴 연결(TIME_WAIT)이 쌓였습니다.
- 이제 연결 하나를 계속 씁니다. 저장 중 MySQL 오류가 나면 그 연결을 닫고, 메시지는 받았다고 응답하지 않습니다. 브로커가 다시 보내 주면 새 연결로 저장합니다.
- "DB에 저장한 뒤에만 받았다고 응답" 방식은 그대로입니다.

## 6. 검증

- 가짜 DB 연결로 25가지 경우를 시험해 모두 통과했습니다. 새 형식·예전 형식·거부, 64자 제한, `EVENT` 기록, 연결 재사용, 오류 뒤 재연결, `ALTER` 전 DB를 확인했습니다.
- **실제 MySQL과 브로커에서는 아직 실행해 보지 않았습니다.** SQL은 테스트 DB에서 먼저 실행해 주세요.
